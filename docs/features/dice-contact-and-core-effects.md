# Dice contact, lettering, sound and core effects

The shared engine serves Dice Forge and full-screen character rolls. Generated outcomes remain authoritative. A constant solid symmetry applied to the entire simulated path selects the result before playback; the end of a roll never seeks a number.

## Landing invariant

`dice-contact-rocking.ts` evaluates gravitational potential from the actual convex mesh's support height. Angular momentum carries the solid through flat contact. Each contact loses energy; insufficient energy to cross the next tipping barrier produces a smaller rock back onto the face. Crossing a barrier selects a new support face without changing pose or velocity. Contact constants cannot be changed in Forge. Sleep requires completed flat contact and negligible horizontal motion.

The old critically damped pose spring and timeout-based animation compression are removed. Saved `settleTimeout` values remain readable but cannot alter physical playback. Both hosts use requestAnimationFrame. Collision geometry includes bevels; dragon ornaments remain a visual layer over the convex collision solid.

## Lettering

- Size ranges from 40–300%. A common physical size is requested; each face fits its own ink bounds. Percentile labels no longer shrink every die. The upper slider range fills the printable area with outline padding. D4 corner values stay coherent.
- Dragon number planes are 0.029 face radii above the base facet, adjacent to 0.0275-radius scale crests. Hollow castings are dressed to 0.027 radii so strands do not cover the inlay. The previous 0.16-radius floating offset is removed.
- Nordic Runes, Elven Flowing Script and Ring Inscription are original numeral fonts generated by `scripts/build_dice_fantasy_fonts.py`. Self-hosted WOFF2 assets are not extracted game or film fonts. Existing Nordic presets resolve to the new carved face.

## Sound and effects

Profiles identify the die and contact surface: plastic/metal on glass, wood, felt and plastic have separate contact noise and damped body/table modes. Metal-on-metal, wood-on-wood, plastic-on-metal and stone remain available. Bell accents sit beneath the contact, at least 1.1 seconds apart. Four buffer variations are cached; playback is capped at 12 voices.

Crit effects import canonical EffectBuilder sources directly through TypeScript aliases. All 40 caster/target compositions and 110 applicable core styles use `BabylonEffectRuntime`; the generic ring/particle approximation is removed. The shared dice editor embeds EffectBuilder's `LayerControlsComponent` and its renderer-settings schema, exposing colors, blend, opacity, timing, particles and lighting. Definitions persist with the dice configuration. Legacy IDs map to distinct compositions.

The dice overlay permits four layers, 96 primary particles per layer, up to five seconds per layer and 1.5 seconds of delay. Runtime-owned meshes, materials, targets and lights are disposed on completion or replacement. Gameplay, summon and teleport choreography are excluded from cosmetic dice effects.

## Performance and verification

Effect/audio edits do not rebuild dice. Visual sliders coalesce over 80 ms. Dragon geometry has a 250,000-vertex cache limit. Static glow avoids pulse calculations. A local seven-die sample took about 23 ms to plan, with approximately 2–4 ms CPU render work per frame on the test machine; these are not cross-device GPU guarantees.

`node scripts/test_dice_motion.cjs` checks 112 seeded rolls, every result symmetry, all shapes/types, extreme pools, three or more floor contacts, no late flips, diminishing rock excursions and timeout-independent duration. Browser regressions exercise all fonts at maximum size, D4 corners, engraving and legacy circle settings. `scripts/dice-effects-regression.ts` checks all 150 native styles and complete scene resource cleanup.

Run `dotnet build` and `npm run build` from an isolated checkout containing canonical `effectbuilder-studio/src` before release. Install both frontend and EffectBuilder dependencies first (`npm ci --prefix frontend` and `npm ci --prefix effectbuilder-studio`); the shared controls resolve their headless directives and TypeScript helpers from the EffectBuilder package. Angular and Babylon aliases keep the frontend runtime versions shared. An isolated verification build may point both dependency directories at the same installed frontend dependency tree.
